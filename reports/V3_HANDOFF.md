# V3 handoff — train-only CV and validation analysis

Status: V3 robustness analysis completed; no V2/V3 test evaluation. V1 and V2 historical configurations, models, predictions and scores remain unchanged. Source settings are in `configs/experiments_v3.yaml`; V3 outputs, notebook execution record and intermediate training features are in ignored `results/v3/`. Reproduction commands are in README. `python -m scripts.check_v3_artifacts` independently verifies CV partitions, prediction-derived macro F1, summary statistics, validation per-class metrics and provenance. Only trusted local artifacts should be used.

Protocol: E1 pixel k=1; E4 HOG 8 + HSV, k=5 Euclidean distance weighting; E6 same HOG + HSV, 128-component randomized PCA, k=3 cosine distance weighting. All are the historical validation-selected winners. Same 5-fold stratified split of official train, shuffled seed 42: 816 fitting and 204 holdout samples per fold, two holdout examples per class. Validation and test IDs are excluded from all folds. PCA is fit separately on each training fold. E6 PCA seeds 42/7/123 use the same folds; E1/E4 do not have randomized fitting. No hyperparameter search or test evaluation is performed here.

The roughly 0.0080 E6/E4 mean gap for seed 42 is smaller than the observed fold spread, which is descriptive rather than a confidence interval. PCA seed means span 0.1932–0.1970 on these fixed folds; this is not evidence about other folds or data. The models and hyperparameters were already selected using validation, so CV does not quantify the complete model-selection procedure. Only eight examples per class fit each fold. The earlier 56-candidate validation search and repeated analysis raise selection-optimism risk.

Validation error analysis uses saved E4–E6 predictions and official labels, validates them against V2 confusion matrices, and exports precision, recall, F1, support and predicted count per class. E6 has 22 classes with F1=0; each has ten validation samples. Most frequent directed errors: 24 → 11 and 94 → 32, four each. Example images in `results/v3/figures/E6_confusion_examples.png` show red/pink class-24 flowers against green foliage (6814, 6819, 6834), and class-94 subjects at notably different scales and backgrounds (7336 close view, 7386 smaller cluster against dark background). Photos 4260 and 4296 of class 18 differ in apparent illumination and crop. Shape, color, background, scale and lighting could influence HOG/histogram distances, but these observations do not establish the cause of a prediction; no controlled attribution was performed. Class names were not mapped here.

Resource comparison, five-fold means for seed 42: E1 12,288 dimensions, fit 0.0082 s, predict 0.0580 s, isolated worker peak RSS 343.8 MiB; E4 1,812, fit 0.0040 s, predict 0.0234 s, peak 214.1 MiB; E6 1,812 → 128, PCA fit plus train transform and K-NN fit 0.0278 s, holdout transform and predict 0.0026 s, peak 217.0 MiB. Worker peaks include interpreter, libraries, entire train feature matrix and temporary arrays; not per-model memory or portable budgets. Fit/predict times exclude loading and extraction. Decode/resize/normalize of all 1,020 training images took 2.271 s, pixel vectors 0.002 s, HOG+HSV 1.161 s. Machine, filesystem cache and concurrency affect timings.

Final protocol proposal: keep E6 fixed at its V2 settings, including PCA seed 42, with PCA and K-NN fitted on official train only. Freeze code/config, source hashes and metrics before any new test use; after explicit authorization run the fixed model once on the official test and publish accuracy, macro/weighted precision/recall/F1, confusion and errors regardless of outcome. Never tune or choose between E4 and E6 from that test. Training on train+validation would be a different, predeclared protocol and its result is not directly comparable to the current train-only model. V1 E1 test was already evaluated and inspected, so the official test is not untouched for the project as a whole; disclose exposure and obtain a new independent holdout for stronger generalization claims. Class imbalance and possible correlated/near-duplicate images remain unquantified.

V4 priorities: (1) obtain independent held-out data or design a nested selection protocol with a new final holdout; (2) investigate duplicate or near-duplicate images and data provenance; (3) test specific error hypotheses with predeclared, train-only experiments, without feedback from the official test. Do not add models or execute the final test in V3.
